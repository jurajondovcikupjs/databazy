• Definujte:
    • Normalizácia (normalization): Proces organizácie dát v databáze, ktorého cieľom je znížiť duplicitu (redundanciu) dát a eliminovať anomálie pri vkladaní, aktualizácii a mazaní (Insert, Update, Delete anomalies) rozdelením veľkých tabuliek na menšie a definovaním vzťahov medzi nimi.
    • Denormalizácia (denormalization): Zámerný proces spájania menších tabuliek do väčších (vnesenie redundancie) s cieľom zrýchliť čítanie dát a znížiť potrebu zložito vykonávaných operácií JOIN.
    • Dekompozícia (decomposition): Rozloženie jednej relačnej schémy na dve alebo viac menších relačných schém bez straty informácií (bezstratová dekompozícia) alebo závislostí.
    • Relačná schéma (relation schema): Množinový popis štruktúry relácie tvorený názvom relácie a množinou jej atribútov, napr. R(A1, A2, ..., An).
    • Relácia (relation): Podmnožina kartézskeho súčinu domén jednotlivých atribútov; v praktickom databázovom poňatí ide o tabuľku, kde riadky predstavujú entity (tuply) a stĺpce atribúty.
    • Funkčná závislosť (functional dependency): Vzťah medzi dvoma množinami atribútov X a Y v relácii (zápis X → Y), kedy hodnoty atribútov zo skupiny X jednoznačne určujú hodnoty atribútov zo skupiny Y (ak sa zhodujú dvoch riadkov hodnoty v X, musia sa zhodovať aj v Y).
    • Triviálna funkčná závislosť (trivial functional dependency): Funkčná závislosť X → Y, kde množina Y je podmnožinou množiny X (Y ⊆ X), napr. {id, meno} → {meno}.
    • Kľúčový atribút (key attribute): Atribút, ktorý je súčasťou aspoň jedného kandidátneho kľúča.
    • Nekľúčový atribút (non-key attribute): Atribút, ktorý nie je súčasťou žiadneho kandidátneho kľúča.
    • Kandidátny kľúč (candidate key): Minimálny nadkľúč – množina atribútov, ktorá jednoznačne identifikuje každý riadok v relácii a z ktorej nie je možné odobrať žiaden atribút bez straty tejto jednoznačnosti.
    • Kompozitný kľúč (composite key): Kľúč (kandidátny alebo primárny), ktorý pozostáva z dvoch alebo viacerých atribútov.
    • Primárny kľúč (primary key): Zvolený kandidátny kľúč, ktorý slúži ako hlavný unikátny identifikátor riadkov v tabuľke (nesmie obsahovať NULL hodnoty).
    • Nadkľúč (super-key): Libovoľná množina atribútov, ktorá jednoznačne identifikuje každý riadok v relácii (môže obsahovať aj nadbytočné atribúty naviac k kandidátnemu kľúču).
    • Podkľúč (sub-key): Vlastná podmnožina nejakého kľúča. Sám o sebe nestačí na jednoznačnú identifikáciu riadku.
    • 1NF (1. normálna forma): Relácia je v 1NF, ak sú všetky jej atribúty atomárne (nedeliteľné hodnoty) a tabuľka neobsahuje opakovateľné skupiny atribútov.
    • 2NF (2. normálna forma): Relácia je v 2NF, ak je v 1NF a každý nekľúčový atribút je plne funkčne závislý od celého kandidátneho kľúča (neexistuje čiastočná závislosť od časti kompozitného kľúča).
    • 3NF (3. normálna forma): Relácia je v 3NF, ak je v 2NF a žiaden nekľúčový atribút nie je tranzitívne závislý od kandidátneho kľúča (pre každú netriviálnu závislosť X → Y platí, že X je nadkľúč alebo Y je kľúčový atribút).
    • HBCNF / BCNF (Heath-Boyce-Codd Normal Form): Sprísnená verzia 3NF. Relácia je v BCNF, ak pre každú netriviálnu funkčnú závislosť X → Y platí, že X je nadkľúč (aj pre kľúčové atribúty na pravej strane).

    Riešenie:

    • Funkčné závislosti: id → meno, id → pohlavie, resp. id → {meno, pohlavie}. (Meno ani pohlavie nedokážu jednoznačne určiť id, pretože viacerí ľudia sa môžu volať rovnako alebo mať rovnaké pohlavie).

    • Nadkľúč: Akákoľvek množina obsahujúca id, napr. {id}, {id, meno}, {id, pohlavie}, {id, meno, pohlavie}.

  • Pomocou Armstrongových pravidiel a pomocou definície dokážte:
    • (x → y) ∧ (x → z) ⇒ x → yz (Pravidlo zjednotenia / Union Rule)
      • Dôkaz pomocou Armstrongových pravidiel:
        1. x → y (dané)
        2. x → z (dané)
        3. Aplikáciou pravidla rozšírenia (Augmentation) na (1) s x dostaneme: xx → xy, čo je x → xy.
        4. Aplikáciou pravidla rozšírenia na (2) s y dostaneme: xy → yz.
        5. Aplikáciou tranzitívneho pravidla (Transitivity) na x → xy a xy → yz dostaneme: x → yz.
      • Dôkaz pomocou definície: Nech t1, t2 sú dva riadky v relácii také, že t1[x] = t2[x].
        Z x → y vyplýva, že t1[y] = t2[y].
        Z x → z vyplýva, že t1[z] = t2[z].
        Preto t1[yz] = t2[yz], z čoho vyplýva x → yz.
    • (x → y) ∧ (wy → z) ⇒ wx → wz (Pseudotranzitívne pravidlo / Pseudo-transitivity)
      • Dôkaz pomocou Armstrongových pravidiel:
        1. x → y (dané)
        2. wy → z (dané)
        3. Aplikáciou pravidla rozšírenia na (1) s w dostaneme: wx → wy.
        4. Aplikáciou tranzitívneho pravidla na wx → wy a wy → z dostaneme: wx → wz.
      • Dôkaz pomocou definície: Nech t1, t2 sú dva riadky také, že t1[wx] = t2[wx] (teda t1[w] = t2[w] a t1[x] = t2[x]).
        Z x → y a t1[x] = t2[x] dostávame t1[y] = t2[y].
        Keďže t1[w] = t2[w] aj t1[y] = t2[y], platí t1[wy] = t2[wy].
        Z wy → z potom vyplýva t1[z] = t2[z].
        Spolu máme t1[w] = t2[w] a t1[z] = t2[z], teda t1[wz] = t2[wz]. Platí wx → wz.
    • (x → y) ∧ (z ⊆ y) ⇒ x → z (Pravidlo dekompozície / Decomposition)
      • Dôkaz pomocou Armstrongových pravidiel:
        1. x → y (dané)
        2. Aplikáciou reflexívneho pravidla na z ⊆ y dostaneme: y → z.
        3. Aplikáciou tranzitívneho pravidla na x → y a y → z dostaneme: x → z.
      • Dôkaz pomocou definície: Nech t1, t2 sú dva riadky také, že t1[x] = t2[x].
        Z x → y vyplýva t1[y] = t2[y].
        Keďže z ⊆ y, pod-záznam z je plne obsiahnutý v y, teda aj t1[z] = t2[z].
        Platí x → z.

      • Začiatok: {AB}+ = {A, B}
      • Aplikujeme AB → C: {AB}+ = {A, B, C}
      • Aplikujeme BC → AD: {AB}+ = {A, B, C, D}
      • Aplikujeme D → E: {AB}+ = {A, B, C, D, E}
      • Výsledok: {AB}+ = {A, B, C, D, E}
    • Vyplývajú z ℱ funkčné závislosti: AB → D a D → A? Prečo?
      • AB → D: Áno, pretože D ∈ {AB}+ ({A, B, C, D, E}).
      • D → A: Nie, vypočítajme uzáver {D}+ = {D, E}. Keďže A ∉ {D}+, závislosť neplatí.

      • Atribút F sa nenachádza na pravej strane žiadnej funkčnej závislosti, preto musí byť súčasťou každého kľúča.
      • Spočítajme uzávery dvojíc s F a trojíc:
        • {ABF}+ = {A, B, C, D, E, F} = 𝒜
        • {BCF}+ = {A, B, C, D, E, F} = 𝒜
        • {ADF}+ nie je kľúč, ale skúsme {ACF}+: z CF → B dostaneme B, potom AB → C..., teda {ACF}+ = {A, B, C, D, E, F} = 𝒜.
      • Kandidátne kľúče sú: {ABF}, {BCF}, {ACF}.

      • Nie, lebo nie je ani kandidátnym kľúčom.
    • Je AB kompozitný kľúč? Prečo?

  • Uvažujme tabuľku ABC.
    • Navrhnite Lossless/bezstratovú dekompozíciu tabuľky ABC:
      • Ak v ABC platí napr. A → B, bezstratová dekompozícia na dve relácie je: R1(A, B) a R2(A, C). Prienik R1 ∩ R2 = {A}, čo je kľúčom v R1.
    • Navrhnite Lossy/stratovú dekompozíciu tabuľky ABC:
      • Dekompozícia na R1(A, B) a R2(B, C) pri absencii závislostí B → A alebo B → C je stratová (vzniknú falošné riadky / spurious tuples pri spojení).
  • Uvažujme rozklad {T1, T2} tabuľky T.
    • Presvedčte sa, že rozklad bude stratový (SQL kódom a potom aj pomocou kritéria):
      • Pomocou kritéria: Dekompozícia R na R1 a R2 je bezstratová práve vtedy, keď prienik atribútov R1 ∩ R2 funkčne určuje R1 (R1 ∩ R2 → R1) alebo R2 (R1 ∩ R2 → R2). Ak táto podmienka neplatí (prienik nie je nadkľúčom ani jednej sub-relácie), rozklad je stratový.
      • SQL kódom: 
        -- Ak prirodzené spojenie T1 a T2 vráti viac riadkov než pôvodná tabuľka T, ide o stratovú dekompozíciu:
SELECT COUNT(*) FROM T;
SELECT COUNT(*) FROM T1 NATURAL JOIN T2;
-- Ak (NATURAL JOIN count) > (pôvodný count), rozklad bol stratový.
    • Zmeňte jednu hodnotu v tabuľke T, aby daný rozklad bol bezstratový (je prienik NK?):
      • Úpravou hodnoty docielime, aby prienik atribútov obsiahnutý v oboch tabuľkách obsahoval iba unikátne hodnoty určujúce zvyšok atribútov v jednej z tabuliek. Tým sa prienik stane nadkľúčom (NK) danej sub-relácie.
  • Interpretujte R1 ∪ R2, R1 × R2 a R1 ⋈ R2.
    • R1 ∪ R2 (Zjednotenie / Union): Množina všetkých prkov/riadkov, ktoré sa nachádzajú v R1, v R2 alebo v oboch. Podmienka: R1 a R2 musia mať rovnakú schému (rovnaké atribúty a kompatibilné domény).
    • R1 × R2 (Kartézsky súčin / Cartesian Product): Množina všetkých možných kombinácií riadkov z R1 s riadkami z R2. Ak R1 má m riadkov a R2 má n riadkov, výsledok má m × n riadkov.
    • R1 ⋈ R2 (Prirodzené spojenie / Natural Join): Spojenie dvoch relácií cez ich spoločné atribúty, pričom vo výsledku sa zhodujú hodnoty na týchto spoločných atribútoch a spoločné atribúty sa neopakujú.
  • Uvažujme relačnú schému ℛ(𝒜, ℱ), kde 𝒜 = { A, B, C, D }, ℱ = { ACD → B, AC → D, AC → B, D → C }.
    • Skontrolujte, že {AC}+ = 𝒜 a preto AC je KK. Existuje ďalší dvojatribútový KK?
      • {AC}+: Začíname {A, C}. Z AC → D pridáme D → {A, C, D}. Z ACD → B (alebo AC → B) pridáme B → {A, B, C, D} = 𝒜. Teda {AC}+ = 𝒜.
      • Ďalší dvojatribútový KK: Skúsme {AD}.
        • {AD}+: Začíname {A, D}. Z D → C pridáme C → {A, C, D}. Z AC → B pridáme B → {A, B, C, D} = 𝒜.
        • Teda {AD} je ďalší dvojatribútový kandidátny kľúč.
    • Je AC kandidátný kľúč? Prečo?
      • Áno, pretože {AC}+ = 𝒜 (určuje všetky atribúty) a žiadna jeho vlastná podmnožina ({A}+={A}, {C}+={C}) nie je nadkľúčom.
    • Je AC primárny kľúč? Prečo?
      • Môže byť, ak ho tvorca databázy zvolí spomedzi kandidátnych kľúčov ({AC}, {AD}) za hlavný identifikátor.
    • Je AC kompozitný kľúč? Prečo?
      • Áno, pretože je kľúčom a skladá sa z viac ako jedného atribútu (z dvoch: A a C).
    • Je AC nadkľúč? Prečo?
      • Áno, každý kandidátny kľúč je zároveň aj minimálnym nadkľúčom, lebo {AC}+ = 𝒜.
    • Je AD podkľúč? Prečo?
      • Nie, AD je sám o sebe kandidátny kľúč (nie je vlastnou podmnožinou nejakého väčšieho kľúča).
    • Je ℛ v 2NF? Prečo?
      • Kandidátne kľúče sú {AC} a {AD}. Kľúčové atribúty sú {A, C, D}, nekľúčový je {B}.
      • Závislosti s B na pravej strane sú AC → B a ACD → B. B závisí od CELÉHO kľúča AC (nie od samotného A ani samotného C).
      • Áno, relácia je v 2NF, lebo neexistuje čiastočná závislosť nekľúčového atribútu od časti kľúča.
    • Je ℛ v 3NF? Prečo?
      • Skontrolujme netriviálne funkčné závislosti v ℱ:
        1. AC → D: AC je nadkľúč (Platí).
        2. AC → B: AC je nadkľúč (Platí).
        3. D → C: D nie je nadkľúč, ALE C je kľúčový atribút (patrí do KK {AC}). Tým pádom podmienka 3NF stopercentne platí!
      • Áno, relácia je v 3NF.
    • Je ℛ v HBCNF? Prečo?
      • Podmienka BCNF vyžaduje, aby na ľavej strane KAŽDEJ netriviálnej závislosti bol nadkľúč.
      • Uvažujme závislosť D → C: D nie je nadkľúč (keďže {D}+ = {C, D} ≠ 𝒜).
      • Nie, relácia NIE JE v BCNF / HBCNF kvôli závislosti D → C.
